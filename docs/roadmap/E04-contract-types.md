## Цель

Формализовать **тип партнёрского контракта** в модели и интерфейсе: Mudaraba / Musharaka / гибрид Mudaraba+Musharaka. Сделать так, чтобы система **автоматически определяла** тип на основе структуры капитала. Подготовить классификацию по AAOIFI-номенклатуре — для будущей сертификации.

## Контекст и обоснование

Сейчас в коде у нас есть `mudaraba_ratio` (доля прибыли по капиталу) и роли участников `INVESTOR / OPERATOR`. Это работает, но **тип контракта не явный** — он размыт по полям. Для:

- **UX:** оператор не понимает, какой тип контракта он создаёт. Видит только числа.
- **Аудита (E06):** AAOIFI требует явную классификацию (FAS 3 — Mudaraba, FAS 4 — Musharaka, и т.д.).
- **Аналитики:** хотим видеть «у тебя N контрактов Mudaraba, M — Musharaka».

Murabaha и Ijara — **отложены**: не покрываются текущим продуктом, добавятся только если бизнес-кейс это запросит (например, исламский лизинг оборудования).

## Сценарии (use cases)

- **US-1.** Оператор создаёт контракт с инвестором → указывает только сумму инвестора и (опционально) свою сумму → система **сама присваивает тип** (Mudaraba если инвестор 100% / Musharaka если оба вкладывают / гибрид если есть и долевое участие, и mudaraba-коэффициент).
- **US-2.** В карточке контракта **видно**: «Тип: Mudaraba» (или «Musharaka», или «Mudaraba+Musharaka гибрид»).
- **US-3.** В отчётности можно фильтровать соглашения по типу контракта.
- **US-4.** В будущей AAOIFI-документации (E06) можем сослаться на конкретный AAOIFI-стандарт для каждого типа.

## План реализации

### Фаза 1 — Авто-определение типа
Завести поле `contract_type` и сервис, который при создании/изменении контракта вычисляет его. Логика:

```
1. Если в контракте все INVESTOR-партнёры имеют capital > 0, а OPERATOR.capital = 0:
   → MUDARABA (чистая мудараба)
2. Если OPERATOR имеет capital > 0 И INVESTOR имеет capital > 0,
   но mudaraba_ratio == 1.0 (прибыль распределяется чисто по капиталу):
   → MUSHARAKA (чистая мушарака)
3. Если OPERATOR имеет capital > 0 И INVESTOR имеет capital > 0,
   и mudaraba_ratio < 1.0 (есть «бонус» оператору сверх его доли в капитале):
   → MUSHARAKA_MUDARABA_HYBRID (гибрид)
```

### Фаза 2 — UX
Форма создания соглашения: после ввода долей — **подсветка типа** («Это будет Mudaraba-контракт»). Карточка соглашения — явное отображение типа.

### Фаза 3 — AAOIFI-mapping
В отдельном документе (часть `sharia-certification-research.md` или внутри E06) — таблица: «наш `contract_type` → AAOIFI-стандарт». Это активно для E06.

### Фаза 4 (опциональная, отложена) — Murabaha и Ijara
Когда / если бизнес-кейс появится. Не блокирует основной поток.
