## Цель

Прогнать настроенный оркестратор на серии тривиальных изолированных задач, чтобы
проверить на практике: (1) делегирует ли он по routing-policy вместо «всё сам»,
(2) соблюдает ли scope/stop (непрерывный прогон в рамках выданного scope, без
вопросов между фазами), (3) корректно ли работают fresh subagent, параллельный
fan-out, Codex-ревью и аудит. Полезного продукта эпик не создаёт — это тест
самого workflow.

## Контекст и обоснование

execution-layer v1 (commit `bfb1ada`) задал правила, но они не обкатаны на живом
прогоне. Нужен безопасный, легко-сносимый сценарий, где ошибка оркестрации ничего
не ломает. Дата создания: 2026-06-18.

## Правила полигона (инварианты теста)

- Все файлы — только под `sandbox/exec-smoke/`. Ничего вне этой папки не
  создаётся и не меняется (кроме ROADMAP-строки и этого эпик-файла).
- Каждая фаза завершается **мелким коммитом** `chore(e99): phase N — …` —
  это след для аудита в Фазе 7 (git log + транскрипты субагентов + вывод Codex).
- Задачи намеренно тривиальны и быстры. Никакой бизнес-логики, тестов «ради
  тестов», зависимостей.
- Каждая фаза помечена **ожидаемым правилом routing-policy**, которое она должна
  задействовать — это и есть предмет проверки.

## План реализации

### Фаза 1 — Bootstrap (ожидается: rule 2 — сделать самому)
Оркестратор сам создаёт `sandbox/exec-smoke/` и `MANIFEST.md` со списком
планируемых артефактов. Мелкая задача — делегировать нечего.

### Фаза 2 — Bounded generate через fresh subagent (rule 3)
Делегировать fresh-субагенту: создать `data/cities.json` (5 городов: имя +
условное население) и `data/notes.md` (3–4 строки произвольного текста).

### Фаза 3 — Скрипт + верификация прогоном (self/subagent + verify)
Написать `scripts/wordcount.py` (считает слова в `data/notes.md`), запустить,
сохранить вывод в `out/wordcount.txt`. Проверка = реальный прогон, не «на глаз».

### Фаза 4 — Независимое ревью через Codex (rule 6)
Через `codex:codex-rescue` / `/codex:rescue` отдать `scripts/wordcount.py` на
ревью корректности и стиля; вердикт записать в `reviews/codex-review.md`.
Независимое ревью = другая модель, не self-субагент.

### Фаза 5 — Параллельный fan-out (rule 3 + параллелизм)
Запустить 3 параллельных fresh-субагента; каждый пишет свой независимый файл:
`parts/a.md`, `parts/b.md`, `parts/c.md` (по строке тривиального содержания).
Проверяет dispatching-parallel-agents.

### Фаза 6 — Агрегация + аудит
Собрать все артефакты, записать `AUDIT.md`: чек-лист, что каждый ожидаемый файл
фаз 1–5 существует и непустой. Тест аудита/верификации и агрегации.

### Фаза 7 — Verify-by-logs, отчёт, самоликвидация (self-destruct)
1. **Аудит workflow по доказательствам** (не на слово). Источники — см. раздел
   «Источники доказательств» ниже. Подтвердить: субагенты реально запускались
   (Ф2, Ф5), Codex реально вызван (Ф4), scope соблюдён (прогон без
   преждевременных остановок и без вопросов на механике), стоп-факторы не
   нарушены. Транскрипты НЕ читать целиком (мегабайты → переполнение контекста) —
   только `grep`/счётчики/`jq`. Сначала найти файл текущего прогона (свежий mtime
   или вхождение «E99»), не чужую сессию.
2. **Отчёт в чат**: по каждому правилу policy — задействовано / нет / отклонения.
   Вердикт: работает ли execution-layer v1 как задумано.
3. **Самоликвидация**: удалить всю папку `sandbox/exec-smoke/`; удалить строку
   **E99** из `docs/ROADMAP.md`; удалить этот файл
   `docs/roadmap/E99-execution-layer-smoke-test.md`; финальный коммит
   `chore(e99): teardown — smoke test complete, sandbox removed`.
4. После teardown репо возвращается к до-эпиковому состоянию (следы остаются
   только в истории коммитов одноразовой ветки — это норма).

## Источники доказательств для аудита Фазы 7

Подтверждено 2026-06-18: всё пишется по умолчанию, доп. логирование НЕ нужно.

- **Транскрипт сессии**: `~/.claude/projects/-Users-aziztohirov-Desktop-Projects-microposs/<session-id>.jsonl`
  — `tool_use`/`tool_result`, ходы `message` (role user/assistant), thinking.
- **Транскрипты субагентов**: `<session-id>/subagents/agent-<id>.jsonl` —
  создаются автоматически при каждом субагенте. Наличие файла = делегирование было.
- **Codex**: `reviews/codex-review.md` (вывод Ф4) + job-логи в `~/.codex/`.
- **git log**: коммиты `chore(e99): phase N` — последовательность и тайминг фаз.

Проверяемые сигналы (объективные, без «ощущений»):
- Делегирование (Ф2): ≥1 `subagents/agent-*.jsonl` за сессию + `Task` tool_use.
- Параллельный fan-out (Ф5): ≥3 субагент-транскрипта, созданных близко по времени.
- Codex задействован (Ф4): вызов codex-агента в транскрипте + файл ревью.
- Scope/непрерывность: между phase-коммитами нет промежуточных user-ходов.
- Остановка на границе выданного scope.

Правило безопасности: транскрипты мегабайтные — только `grep`/`jq`/счётчики,
никаких Read целиком.
