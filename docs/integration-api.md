
## Заголовки
| Заголовок | Значение | Когда |
|---|---|---|
| `X-Integration-Key` | ключ интеграции `ssk_yespos_live_...` | всегда |
| `Content-Type` | `application/json` | для POST |
| `X-Request-Id` | уникальный id запроса | опц., для идемпотентности POST |

Ключ создаётся в приложении: **Настройки → Интеграции → Добавить ключ** (показывается один раз). Отзыв ключа сразу делает его недействительным.

## Эндпоинты
| Метод | Путь | Назначение |
|---|---|---|
| POST | `/sale` | Событие продажи |
| POST | `/inventory` | Событие по остаткам |
| POST | `/agreement-link` | Событие по договору |
| POST | `/{slug}` | Произвольное событие (`slug`: `[a-z0-9-]`, ≤64) |
| GET | `/agreements` | Список активных инвест-договоров |

Тело POST — произвольный JSON-объект (сохраняется целиком).

## Принцип работы (текущая фаза)
Сейчас эндпоинты только **принимают** запросы по указанным путям и **сохраняют тело целиком** на сервере (raw, как есть). Никакой обработки или валидации структуры пока нет.

Что нужно от вас: присылайте разные виды запросов на соответствующие пути (`/sale` — продажи, `/inventory` — остатки, `/agreement-link` — договоры, `/{slug}` — прочее). Как только получим реальную структуру и форматы передаваемых данных, зафиксируем контракт и на их основе построим логику обработки.

## Ответы
| Код | Тело | Значение |
|---|---|---|
| 201 | `{"id": "...", "status": "received"}` | принято |
| 200 | `{"status": "duplicate"}` | повтор по `X-Request-Id` |
| 400 | `{"detail": "..."}` | неверный `slug` |
| 401 | `{"detail": "..."}` | нет/неверный/отозванный ключ или IP не разрешён |

`GET /agreements` → массив объектов: `id`, `title`, `investor_name`, `profit_ratio`, `capital_amount`, `currency`, `status`.

## Безопасность
Передавать ключ только по HTTPS. Для ключа можно задать allowlist по IP. Ключ в Git/логи не коммитить.
