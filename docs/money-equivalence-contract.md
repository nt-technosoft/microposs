# Money Equivalence Contract — золотые сценарии для E18

> **Назначение:** критерий приёмки рефактора E18. «Вот так нынешняя (E17) система
> двигает и считает деньги — новая ОБЯЗАНА воспроизвести это поведение реальной
> логикой движения, а не подгонкой чисел.»
> **Кто держит:** аудиторская сессия (Claude).
> **Статус:** ЧЕРНОВИК (2026-06-15). Точные эталонные числа фиксируются прогоном
> против **закрытого E17** (после acceptance-зелёного Codex). Ядровые money-числа
> (позиции/conservation/GL) стабильны — acceptance-фиксы S1/S4 трогали только
> отображение (free balance/availability), не математику позиций.

---

## Как проверяется эквивалентность (4 калибра на КАЖДЫЙ сценарий)

Для каждого золотого сценария старая и новая реализация обязаны совпасть по всем:
1. **Числа поле-в-поле** — позиция партнёра (deployed, recovered, profit,
   loss, capital_return_available, provisional_profit_available, negative_position,
   net/owed/withdrawable) идентична старой.
2. **Сохранение** — `residual(карман, валюта)` = **точный 0** по функциональному
   UZS, ≤ε только на native-FX-ноге.
3. **GL идентичен** — множество journal-строк (счёт + сумма) по операции совпадает
   до и после (теги = метаданные, деньги не двигаются).
4. **Anti-drift (новое в E18)** — `replay(GL + провизорный слой) == read-model`.

Принцип: эквивалентность = совпадение **по экономической логике** (числа + сохранение
+ GL), а не «подкрутили, чтобы сошлось».

## Матрица золотых сценариев

> Числа с пометкой ✅ — **проверены прогоном в этой сессии**. Без пометки — каркас
> сценария, точные числа снять прогоном против закрытого E17. Все суммы в UZS, если
> не указано иное.

### G1 — Чистая прибыль, полный цикл
Капитал 70/30, прибыль 40/60. Полностью профинансировано, продано всё в прибыль,
FINAL settlement, выплачены дивиденды + возврат капитала, close прихода и договора.
- Пинит: профит доступен только после settlement; recovered растёт по мере продаж;
  после выплат **free balance ≥ 0 и availability участников ≥ 0** (это и есть фикс
  S1 — контракт ловит регресс); close проходит; read-only после CLOSED.

### G2 — Убыточный венчур ✅ (проверено)
Продано ниже себестоимости, чистый убыток. Пример (proceeds 936 000, deployed
1 200 000): investor recovered **655 200** / loss **184 800**; operator **280 800** /
**79 200**; профита нет; Σclaimable = proceeds, **GAP = 0**. Убыток делится по
capital_share.

### G3 — Смешанный прибыль+убыток (неттинг) ✅ (проверено)
Капитал 70/30, прибыль 40/60, себестоимость 120 000/ед; 5×180 000 (прибыль) +
5×72 000 (убыток). Нетто венчура = **60 000**. После settlement: профит **investor
24 000 / operator 36 000** (нетто×profit_share, НЕ по-сделочно); капитал recovered
**840 000 / 360 000**, loss 0; **GAP = 0**. (Контракт ловит баг по-сделочного сплита,
который давал 104 000/276 000.)

### G4 — Недовзнос в пул (взаиморасчёт) + settle ✅ (заморожено, commit b62a3e1)
Капитал 70/30 (deployed 100), взносы 66/34. Должник (investor) net **+4** (должен пулу);
кредитор (operator) net **−4**, но `withdrawable = 0` — излишек заморожен в товаре, пока
должник не довнёс (`pool_free = total_paid − total_deployed = 0`). После довзноса должника
**4** → `pool_free = 4` → кредитор `withdrawable = 4`. Возврат кредитора **пуловым путём**
(`procurement_id=None`) проходит → обе стороны `net = 0`, `withdrawable = 0`.
- **Гейт доступности** = `partner_capital_positions().withdrawable` (канонический pool-read),
  НЕ legacy `_agreement_partner_available` (тот возвращал 0 → ложный отказ; это и был S4).
- **Conservation:** residual `capital/proceeds/distribution` = **0.00** до и после возврата.
- **FROM_PROFIT после Фазы 1:** одно честное событие «прибыль → капитал»; в истории
  **нет** фейковых dividend/contribution; **числа и GL — те же** (контракт пинит числа+GL+
  conservation, а НЕ доменные строки — иначе залочил бы сам баг, который Фаза 1 убирает).

### G5 — Переплата → долг венчуру → погашение
Дивиденд рано → позже убыток уменьшает долю → over-dividend negative_position; ИЛИ
over-withdrawal. Пинит: negative_position > 0 блокирует close; «Погасить долг» →
negative → 0; close разблокируется.

### G6 — Partner-liability (вина оператора) ✅ (проверено)
5 продано в прибыль + 5 списано negligence. Operator liability negative **660 000**;
repay → **0**, GL **CR 5100** (writeoff DR 5100 660k / repay CR 5100 660k → нетто 0,
НЕ equity); investor made whole (капитал 840 000 + профит 120 000 = **960 000**);
conservation = 0 до и после.

### G7 — Кросс-валюта (USD-себестоимость / UZS-продажа, курс сдвинут) ✅ (проверено)
100 USD @ buy 12 000 (=1 200 000 UZS), продано 10×180 000 UZS:
- курс 13 000: cost_amount **100 USD**, FX-дрейф **+100 000**; capital leg **910 000 /
  390 000** (FX по capital_share); trading profit **200 000 / 300 000** (по profit_share).
- курс 11 000: FX **−100 000**; capital **770 000 / 330 000**; trading **280 000 / 420 000**.
- стабильно 12 000: FX 0; capital **840 000 / 360 000**; profit **240 000 / 360 000**.
- Везде **GAP = 0**, residual = 0 по карману×валюте. FX по capital_share, торговая по
  profit_share — раздельно; авто-конвертации нет.

### G8 — Возвраты (RESTOCK / DISPOSE)
Продать, затем возврат. Пинит: realization сторнируется пропорционально; повторный
сабмит **идемпотентен** (второй возврат не создаётся); conservation держится.

### G9 — Несколько приходов под одним договором
Close каждого прихода отдельно; договор закрывается только после всех закрытых
приходов и сведённых net-позиций + сведённого пула.

### G10 — Гейты close + read-only
Попытка close при: нераспроданном товаре / без FINAL / negative_position / висящем
claim → блок с человеческими причинами. После CLOSED — операции, меняющие экономику,
запрещены.

## Свойство (property-based, поверх примеров)

Любая последовательность money-событий → **каждый карман × валюта Σ = 0** (точный 0
по UZS). Один property-тест сильнее десятков примеров. Войдёт в тест-режим E18 (Фаза 7).

---

## Что контракт ОБЯЗАН поймать (анти-регресс — реальные баги)

- по-сделочный сплит профита вместо нетто (G3): 104 000/276 000 ≠ 24 000/36 000;
- free balance/availability в минус после recovered-возврата (G1/S1);
- незакрытие net кредитора после возврата (G4/S4);
- liability, кредитованный на equity вместо 5100 (G6);
- FX, размазанный по profit_share вместо capital_share (G7);
- фейковые dividend/contribution в FROM_PROFIT (G4/Фаза 1).
